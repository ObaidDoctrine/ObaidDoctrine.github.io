# OBAID DOCTRINE — Facebook 90-Day Automation Setup\n\n## Current architecture\n- Existing article publisher remains in `.github/workflows/facebook-publish.yml` and `.github/scripts/publish-facebook.sh`.\n- New automation uses the existing Supabase project for persistent content, publication logs and analytics.\n- GitHub Actions runs the scheduler every 15 minutes.\n- The private control center is `/admin/facebook-automation/`.\n- Facebook Reels are feature-gated until the live Meta permissions/API behavior are verified with the real Page credentials.\n\n## One-time production configuration\n\n### 1. Create the admin account\nIn the Supabase project Auth dashboard, create the private admin user.\nThen run this SQL using that user's Auth UUID:\n\n    insert into public.facebook_admin_users (user_id)\n    values ('YOUR_SUPABASE_AUTH_USER_UUID')\n    on conflict (user_id) do nothing;\n\nDo not put the user's password or any service-role key in the repository.\n\n### 2. Add GitHub Actions secrets\nRepository: `ObaidDoctrine/ObaidDoctrine.github.io`\nRequired:\n- `SUPABASE_URL` = `https://nrckrzgxpxfwuyodbylg.supabase.co`\n- `SUPABASE_SERVICE_ROLE_KEY` = Supabase server/service key\n- `FB_PAGE_ACCESS_TOKEN` = the existing Meta user token already used by the article publisher\nThe service key must exist only as a GitHub Actions secret.\n\n### 3. Schedule content\nCreate records through the private control center.\nEach day has exactly three slots: morning — Human Behaviour; afternoon — Life Reality / Human Nature; evening — Self-Awareness / Character.\nThe database enforces one record per day/slot and supports Day 1–90, giving a maximum campaign shape of 270 records.\n\n### 4. Safe link-post test\nCreate one test record with `content_type = link`, `status = scheduled`, a future `scheduled_at`, and a unique topic/idempotency key.\nThe scheduler performs a Page-feed preflight before a link post. If it cannot verify the Page feed, it refuses to publish rather than guessing and risking a duplicate.\n\n### 5. Reels\nThe scheduler contains the Reel upload/publish path, but `ENABLE_REELS=false` is the production default.\nDo not enable it until current Meta permission set, Page task access, upload behavior and live credentials have been verified. This is intentionally fail-closed.\n\n## Important limitation\nThe database cannot make Facebook's external publication and PostgreSQL update one atomic transaction. The system therefore uses database state, row locking, persistent idempotency keys, publication logs, Page-feed preflight for link posts, stale publishing recovery and bounded retries.\nThis substantially reduces duplicate risk, but it is not a mathematical two-phase transaction with Facebook.\n\n## Existing article automation\nDo not delete, rename or disable `.github/workflows/facebook-publish.yml` or `.github/scripts/publish-facebook.sh`.\nThe new workflow is separate: `.github/workflows/facebook-90day-automation.yml`.
